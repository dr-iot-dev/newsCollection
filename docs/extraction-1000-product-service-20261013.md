# 商品サービスのAI・IoT記事1,000件：埋め込みと高密度コア

実施日：2026-10-13。状態：完了。1,000件の埋め込み値を保存し、高密度コアの抽出と実データ検証を完了した。

## 確定した対象条件

- 公開PR TIMES記事のうち、AIまたはIoTの記事。分野判定はタイトルまたは会社概要等の見出し以前の本文冒頭1,200文字。
- タイトルに[111語の除外語](extraction-word-count-spec-20261012.md)が一つも含まれない。追加8語：強化、推進、刷新、選出、展開、人材育成、誕生、出資。NFKC・casefold後の部分一致。旧記事も再判定する。
- 公式の「種類」が商品サービス、種類IDが01。公式HTMLの種類リンクから確認し、未知・曖昧・別種類を拒否する。本文で自称する「商品サービス」は種類の根拠にしない。
- Discoveryの50候補の一致候補数が5以上。4以下を除外し、この条件まで満たす記事を1,000件確保する。

公開キーワード検索は種類フィルタを併用しない仕様だった。[PR TIMES公式の説明](https://prtimes.jp/main/html/rd/p/000001699.000000112.html)では、種類を併用する詳細検索はメディアユーザー向け機能。ユーザーからアカウントがない旨と、代替の「公式の種類を確認して1,000件を集める」方法への明示選択を受け、公開AI／IoT検索→記事の公式種類確認という順序で進める。ログイン制限の回避や、無視される種類パラメータの利用はしない。

## DBと検索対象

既存DBを[変更前バックアップ](../.local/extraction-1000-20261013/source-backup/iot-articles.sqlite)へ退避した。追加8語だけの初回再判定で、従来の対象200記事から33記事を除外し、タイトル・分野条件の通過は167記事、一致候補数5以上は105記事となった。[初回の除外記録](../.local/extraction-1000-20261013/policy-v3-impact.json)。

require_product_service=1をコーパスに保存する。種類確認結果はterm_release_type_screeningsに公式URL・種類ID・種類名・HTMLハッシュ・確認日時として保存する。release_type_excludedフラグを設け、未確認も1とする。本文を削除せず監査用に残し、記事読み出し・件数・MATERIALIZED CTEによる候補検索の前段から除外する。新規記事は種類の確認なしには本文を検索用term_articlesへ保存しない。

AIとIoTの公開検索は各10,000件の上限まで取得して941件が条件を通過した。残り59件はAIに属する別表記の人工知能・機械学習・LLM・AIoTでも補充した。各記事の分野・種類・タイトル・一致候補数の条件は変えない。

取得済みの公式HTMLスナップショットは種類確認に再利用する。未取得のタイトルが除外語に一致した場合は本文を取得しない。公開HTMLを取得した後も実タイトルと種類を検証し、AI／IoT分野条件を適用する。SQLiteへ保存した記事と語彙に対して候補数を数える。収集中の停止件数を判断する増分カウントは、DBと同じnormalized_term・phrase_match相当の語境界判定でconcept_idを一度だけ数え、完了時に全件をDB SQLで照合する。

収集は専用コンテナで直列実行。通常の定期収集設定は変更せず、このバッチに1秒以上の間隔を設定した。robots.txtの取得許可・Crawl-delayを確認し、サーバーの429時は指定時間以上の待機と5秒以上への間隔延長を行う。チェックポイントを保存し、処理済みの記事は再取得しない。

## 埋め込みと再利用

モデルは既存と同じtext-embedding-3-small、1,536次元。入力は保存済みタイトル、空行、本文全体。長文は6,000 UTF-8バイト以内に区切り、各区間のバイト数で加重平均してL2正規化する。文字を切り捨てない。

以前のarticle-values.sqliteを読み取り専用で開く。モデル、表現方式、タイトル・本文の全文ハッシュが一致する記事の値をそのまま再利用する。F IDは今回の解析内の通し番号とし、旧記事はprevious_f_idに前回126件の解析IDを記録する。

未計算記事でも、同じモデル・同じ入力ハッシュの区間値は再利用する。完了したAPIバッチをDBへコミットし、途中失敗後に同じ区間を再送信しない。再利用される記事が今回の除外条件を通るかは、旧キャッシュとは別に現在のコーパスで確認する。

1,000件未満ならAPI呼び出しを開始しない。1バッチ最大16区間、送信先はhttps://api.openai.com/v1/embeddings。取得済み本文と返却ベクトルを記録し、APIキーはファイル・ログ・引数へ保存しない。API送信はユーザーの明示指示に従い実行する。

今回の目的では全499,500ペアの距離表の再生成は行わず、記事別値とクラスタ結果を保存する。

## 料金の推定方法

[OpenAI公式のtext-embedding-3-small単価](https://developers.openai.com/api/docs/models/text-embedding-3-small)を2026-10-13に確認：通常の同期APIは100万入力トークン当たり0.02米ドル。Batch APIの割引は使用しない。

- 今回のAPI料金推定＝今回の成功応答usageの累計入力トークン数 × 0.02 ÷ 1,000,000。
- 全対象記事の平均＝今回の推定料金 ÷ 1,000。
- 新たに値を生成した記事当たり平均も併記。既存値の再利用分は今回の増分料金0。
- UMAP・HDBSCANはローカルで実行し、OpenAI API料金を追加しない。料金推定はAPI利用分で、税・為替・ローカル計算機の運用費を含めない。請求確定額ではない。

## 高密度コア

全1,000ベクトルをL2正規化し、UMAP（metric='cosine'、n_components=15、n_neighbors=15、min_dist=0、random_state=42）で縮約する。HDBSCANは縮約空間のユークリッド距離でmin_cluster_size=5、min_samples=5、leaf方式。ノイズに分類された記事はコアから除く。

各クラスタで、帰属確率0.9以上の上位3件と、元の1,536次元空間の正規化重心に近い上位3件の共通部分をコアとする。確率上位と重心上位の候補リストも別途保存する。内容の正解率や純度を帰属確率として解釈しない。元空間のコア間類似度を併記し、シード7・21、縮約10・20次元、近傍30、最小サイズ8の6通りでも確認する。

## 再実行用コマンド

最終候補カウントをDB SQLで保存してから、埋め込みとコアを実行する。

```powershell
news-weave extraction count --database .local/extraction-1000-20261013/iot-articles.sqlite --corpus iot-20261012 --vocabulary .local/extraction-word-count-20261012/vocabulary.json --output .local/extraction-1000-20261013/counts --minimum-articles 1000
news-weave extraction embeddings --database .local/extraction-1000-20261013/iot-articles.sqlite --corpus iot-20261012 --counts .local/extraction-1000-20261013/counts/counts.json --output .local/extraction-1000-20261013/embeddings --reuse-database .local/article-group-f-distances-20261013/article-values.sqlite --minimum-articles 1000
news-weave extraction cores --vectors .local/extraction-1000-20261013/embeddings/article-values.json --output .local/extraction-1000-20261013/cores
```

embeddingsの--prepare-onlyは入力を保存してAPIを呼ばない。coresは任意依存news-weave[clustering]が必要。

## 公式タイトルの修復

PR TIMESの一部の公式HTMLには、h1見出しに置換文字（�）が入り、同じページのog:titleには正常なタイトルがあった。正常な公式メタデータから保存タイトル707件を回復し、タイトル・分野・種類の条件と全件のSQLカウントを再判定した。Eは1,756件、Fは1,000件のままであり、本文の置換文字は0件だった。対象Fの318件の入力タイトルが変わったため更新し、変更のない682件の全文値と一致する区間値は再利用した。旧キャッシュから初回再利用した84件のうち27件もタイトル修復対象だったため、最終的な旧全文値の再利用は57件。

検索対象外の旧保存記事1件は取得監査DBに正常タイトルの根拠がなく、修復せず対象外のまま保持した。Fの全1,000件に置換文字がないことを検証した。[修復根拠と前後タイトル](../.local/extraction-1000-20261013/title-repair.json)。今後は見出しに置換文字があれば正常な公式JSON-LD／og:titleを使い、欠損文字を推測しない。文字化け回復と正常見出しの優先を含むコンテンツ抽出の22テスト、Ruff、型検査が通過した。

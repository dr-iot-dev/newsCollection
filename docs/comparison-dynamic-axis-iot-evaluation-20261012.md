## AI検証通過後に残った問題

追加の原文照合で、少なくとも以下を確認した。

- obniz Nowの「データ識別・保存」「オフライン中の挙動記録」から、可視化や推移グラフまで回答へ拡張している。取得済み本文ではその明記を確認できない。
- ラトックの「温度データ自動記録」「異常時通知」から、「異常時ログあり」を追加している。本文で異常時ログの明記は確認できない。
- Nobest-Tagを「クラウドで監視できる対象」の回答に含めているが、本文にクラウド方式の明記はなく、その未確認条件が回答から落ちている。

これは非対応の判定ではなく、取得済み資料だけでは回答の裏付けが不足するという判定である。引用位置が正しくても、引用からの意味の拡張は残り、別モデルの独立検証も見逃し得る。形式適合と内容の正確さが別であることは、[OpenAI公式資料](https://developers.openai.com/api/docs/guides/structured-outputs)とも整合する。

## 現行方式との比較・限界

同じA・B・Cの現行ペア方式では4項目を生成したが、過半数を満たしたのは監視対象・通知の2項目で、最低3項目に届かず保留した。新方式は同じ群で8候補・過半数5項目を得たが、値修正前の独立検証は保留である。

単一のIoT資料集合と少数の試行であり、汎用的な精度向上や入力順への不変性は証明していない。初回の軸や抽出回答に複数の小項目が混在する例もあり、粒度の安定化は残る課題である。一部の保存済みタイトルには置換文字がある。

次の改善は、各セルの回答を原子的な主張へ分け、主張ごとに引用が直接裏付ける範囲と限定条件を検証すること。Discoveryに値判定の条件を戻す必要はない。

## 実装した内容

ステップ2は約50語を目標とし、構造化出力の上限を12語から50語へ変更した。初期資料ごとに最大20語の候補を抽出し、原文根拠・採用理由・同義語統合・一般語除外を保ってカテゴリ統合する。特徴語専用の入力・出力上限を200,000文字・16,000トークンにした。根拠付きの異なる特徴語が不足すれば実件数と理由を記録する。

ステップ3は全組合せ検索を廃止し、各キーワードを単独で検索する。公開検索画面と同じ追加読込経路から1ページ40件ずつ取得し、各語につき150件まで記事ID（正規化URL）・タイトルを保存する。URLごとに検索ヒットしたキーワードID集合を保存し、その要素数を語数として数える。

通常は各キーワードの結果に同じURLは1回しか現れない。集合での保存はページ間重複や中断後の再取得への対策であり、本文中の出現回数を数える意味ではない。K1・K2・K3の検索に同じURLが現れた場合は3語、K1の結果を再取得しても1語のままとなる。

全キーワードの検索結果が揃ってから、3語以上のURLを本文取得候補にする。本文の3概念一致、カテゴリ所属、重複・品質条件を確認して資料群Aを最大100件へ確定する。埋め込み、距離、群B、第三資料の試行、10ペア失敗時だけ探索不成立とする終了条件は維持した。

## 回帰検証と運用上の制限

関連回帰試験は208件通過・2件skip（SQLite/PostgreSQL）。50語受理・51語拒否、150件までのページ送り、2語と3語の候補判定、URLのページ重複・再取得、ページ予算での停止と再開、検索条件変更の拒否、不正JSON・ページ応答・非公開経路の拒否、CSV出力、既存の10ペア終了条件を検証した。[試験記録](../.local/pair-keyword-search-v1-evaluation-20261011/keyword-search-tests.xml)を保存した。ruffとmypy（120ファイル）も通過した。

50語すべてに150件以上の結果がある場合、検索結果は最大7,500行、追加読込は約200ページとなる。既存の取得間隔・ページ予算は維持し、予算超過時には同じ実行IDの語・ページ位置から再開する。結果が150件に満たない語は実件数と終了理由を保存する。今回の公開経路許可は設定ファイルのDB同期後に適用される。既存サービスの再配備や、旧方針の完了済み探索の再実行はしていない。

一般語の追加除外後に、探索・AI診断の関連117件を再確認してすべて通過した。APIなどの単独一般語で50語の目標を埋めない条件を含む。[最終試験記録](../.local/pair-keyword-search-v1-evaluation-20261011/keyword-final-tests.xml)を保存した。

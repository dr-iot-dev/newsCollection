# Discovery候補数制限の撤去とIoT再抽出

実施日：2026-10-12。比較項目の抽出だけを対象とする。

## 修正内容

初期案の6〜8候補という目安を、プロンプトと候補契約の最大8件制約として実装したことが、候補を8件に圧縮する原因だった。候補発見段階で件数を制限した設計を修正した。

- プロンプトの6〜8件という目安を撤去した。
- 原文引用付き候補／段落参照付き候補の両スキーマから最大8件制約を撤去した。
- 独立して回答できる内容を分割し、同じ内容の言い換えだけを統合する。
- 一部の記事だけに現れる仕様・機能・提供条件も候補として列挙する。
- 後段の採用数とDiscovery候補数は分離する。今回は後段を実行していない。

## 再抽出の条件と件数

保存済みの同じIoT記事を入力し、gpt-5.2でDiscoveryだけを再実行した。値抽出、選定、AI検証、比較表・記事生成は実行していない。入力上限200,000文字、出力上限16,000 tokens。候補件数の上限はないが、API出力容量は有限であり網羅性を保証するものではない。

## この実行後に修正した評価方針

当初は機械的な細分化を良いことと判断し、「トリガー/ノード拡充」の複合を課題とした。この判断を撤回する。一般的な機能名として比較しない細目は、トリガーや拡張機能などの共通項目へまとめる方が適切である。

- 温度監視セットと設備監視セットの価格は、製品間比較では共通の「価格」にまとめる。
- 軸名は短い一般名詞とし、括弧・例示・長い修飾を外す。
- 記事固有の細目の網羅ではなく、同分野の他製品にも適用できる共通項目を抽出する。
- 通常の語句検索で記載を探せる検索語を持たせる。

上の74／58候補は機械的細分化の指示による過去の出力であり、現在の推奨候補ではない。現行の抽出方針・実行結果は[検索用共通軸の記録](comparison-dynamic-axis-discovery-searchable-20261012.md)を参照。

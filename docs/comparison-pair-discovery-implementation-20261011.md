# PR TIMESペア探索の実装記録（2026-10-11）

[修正計画](comparison-prtimes-pair-selection-plan-20261011.md)の段階1〜5を実装した。評価カテゴリはユーザー指定の「生成AI」である。段階6では生成AIカテゴリの10資料評価を完了した（10ペア不成立）。既存の自動記事生成への接続（段階7）は後続工程として扱う。

## 実装した流れ

1. 承認済みのPR TIMESキーワードカテゴリから、調査・事例等のタイトルを除外して初期10資料を取得する。
2. 指定カテゴリ内の技術・機能・専門用途の違いを表す語を、各資料の原文根拠と採用理由付きでAI抽出し、約50語（上限50語）のカテゴリ特徴語Kを選ぶ。原文が不足すれば語数と理由を記録する。カテゴリ名・汎用語は除く。
3. Kの各語を単独でPR TIMESの公開検索に掛け、各語につき最大150件の結果ID（正規化URL）・タイトルを保存する。URLごとに異なる検索ヒット語を集計し、タイトル除外を通った3語以上の候補だけ本文取得する。記事タイトルを再確認し、本文3概念一致と取得品質を確認して最大100資料を群Aへ保存する。カテゴリタグは必須にしない。
4. URL・連絡先等を除いた本文の実埋め込みを作る。長文は全体を分割し、各部分のベクトルを加重平均して正規化する。
5. 群Aの全ペアをコサイン距離で順位付けする。
6. 順位の小さいペアから比較項目をAIで抽出し、その項目を固定する。
7. 群A内で3項目以上一致する群Bを抽出する。
8. ペアの両資料への平均距離が小さい第三資料から試す。
9. 3項目以上で各項目2/3資料以上に原文根拠があり、別モデルによる検証が通った場合に採用する。
10. 不合格なら同じペア・項目で第三資料を順に試し、群Bを使い切った後に次ペアへ進む。
11. **10ペアを試行完了してすべて不合格だった場合だけ、探索不成立（exhausted）とする。**
12. 実行IDを起点に、本文・版・取得記録・集合・距離・比較項目・根拠・全試行を保存する。

同距離は資料IDで安定順位を決める。特徴語の抽出・統合には指定カテゴリと汎用語除外条件を渡し、カテゴリ内の区別を説明する `distinction_reason` を必須とする。出現数は補助情報とし、頻出する一般語で検索一致数を増やさない。検索ラベル・別名は引用された具体的な語を保持し、汎用的な部分語へ短縮しない。同義語の重複を統合し、カテゴリ名・汎用語・引用にないラベルや別名を除外する。除外判断・除外別名・採用理由・前後件数を監査記録へ残す。`category-distinction-v3-fifty` と `per-keyword-results-v1` は実行のfingerprintに含め、旧Kと下流結果を新方針へ流用しない。引用位置は、引用文が原文の一意な場所に完全一致する場合だけ確定する。曖昧な引用や原文にない引用を補完しない。応答の修正は1回に限り、費用・呼出数へ含める。

## 実行方法

Python 3.13環境で収集元をDBへ同期し、以下を設定する。

- `AI_PROVIDER=openai` と `AI_API_KEY`
- `AI_COMPARISON_PLANNER_MODEL`：特徴語・比較計画
- `AI_COMPARISON_ASSESSOR_MODEL`：特徴の抽出
- `AI_COMPARISON_VERIFIER_MODEL`：前二者と異なる独立検証モデル
- `AI_EMBEDDING_MODEL`、`AI_EMBEDDING_REVISION`
- `AI_PAIR_KEYWORD_MAX_INPUT_CHARS=200000`、`AI_PAIR_KEYWORD_MAX_OUTPUT_TOKENS=16000`：特徴語抽出・統合だけの上限。その他の生成処理は従来の上限を使う。

モデルを既存の環境へ自動設定しない。実資料評価では既存の評価と同じ生成モデルを用い、埋め込みは [OpenAI公式モデル仕様](https://developers.openai.com/api/docs/models/text-embedding-3-small)で確認した `text-embedding-3-small` を明示設定している。

```powershell
news-weave comparison-pair discover --source prtimes-generative-ai --output .local/pair-genai --call-budget 80
news-weave comparison-pair resume 実行ID --output .local/pair-genai --call-budget 80
news-weave comparison-pair export 実行ID --output .local/pair-genai
```

取得上限・呼出予算は1回の起動ごとに適用される。既存の5秒間隔・ページ数・robots/規約・許可URLを守る。予算やページ上限で中断した場合は同じ実行IDを再開する。既に確定した取得・AI応答・ベクトル・第三資料の不合格結果を再実行しない。設定・モデル・方針が変わった再開は拒否する。

`discover`/`resume` は採用時に終了コード0、それ以外の状態は2、コマンドエラーは1を返す。標準出力は状態JSONで、実行ID・状態・理由を含む。

## 状態と終了条件

| 状態 | 意味 |
| --- | --- |
| selection_passed | 3資料が成立。10ペア未満でも成功終了 |
| exhausted | 10ペアを試行完了し、比較が成立しなかった |
| paused_budget | 呼出予算・取得ページ上限で中断。未完了ペアは消費しない |
| waiting_retry | API・通信・応答検証の失敗。同じ場所から再試行できる |
| insufficient_pairs | 利用可能なペアが10未満。探索不成立とは区別する |
| insufficient_sources / insufficient_keywords | 必要な資料・特徴語が不足する |
| failed_configuration | モデルや収集元の設定不足 |

## 保存・出力

既存の `module_messages` に `comparison_pair_run` のチェックポイントと `comparison_pair_event` の工程記録を保存する。新規DB移行は不要。AI履歴は既存 `ai_runs`、原文取得は `raw_snapshots`・`items` へ保存する。PostgreSQLでは専用接続のadvisory lockで同一実行の重複起動を拒否する。

- `audit.json`：全状態・工程記録・AI実行参照・ベクトル・根拠
- `ai-runs.json`：修正・不合格を含むAI履歴、トークン、時間、取得可能な費用
- `keyword-search-results.csv`：各語の結果ID・URL・タイトル・ページ・順位・snapshot
- `keyword-search-summary.csv`：語別保存数・150件の目標・完了状態・終了理由
- `article-keyword-counts.csv`：記事ID別の検索ヒット語ID集合・語数・本文一致語数・除外理由
- `pair-distances.csv`：全ペアの資料ID・順位・距離
- `third-distances.csv`：試行済み／現在進行中のペアの第三資料順位・両側距離
- `coverage.csv`：各第三資料試行の項目別根拠数・採否
- `report.md`：件数・状態・履歴・採用資料
- 合格時の `selection.json`：凍結hash付きの3資料・比較計画・根拠・検証結果
- 合格時の `comparison.md`：記事作成用の比較資料表・出典

原文を含む監査ファイルはローカル評価出力として保管する。公開用のプロンプト・JSON Schemaには原文や秘密情報を含めない。

## カテゴリタグ条件の撤廃とタイトル除外

ユーザーの指示に従い、検索記事の「生成AI」タグによる所属確認を撤廃した。カテゴリは初期一覧と特徴語抽出の文脈に使う。検索記事では `category_proof` を空欄にでき、群Aの検証もこの値を要求しない。初期資料の同フィールドは一覧の取得元を表し、記事タグの証明ではない。

タイトルに「調査」「事例」「アンケート」「ランキング」「レポート」「ホワイトペーパー」「白書」「セミナー」「ウェビナー」「勉強会」「講演」「対談」「インタビュー」「イベント開催」「展示会」「書籍」「出版」「刊行」「受賞」を含む資料を対象外とする。判定関数は `app/core/comparison_pair_discovery.py` の `excluded_title_terms`。本文内の出現だけで除外せず、NFKCで正規化したタイトルの部分一致を使う。

初期資料では除外分を採用数に数えず、一覧の次資料を確認する。検索では最大150件の結果IDと記事別語数を保持したうえで、タイトル除外を通った3語以上のURLだけを本文取得する。記事ページのタイトルでも再確認し、検索結果タイトルと異なっても除外する。群Aの入口でも同じタイトル条件を検証する。

初期資料の取得順・採否・除外語は `initial_results` と新しい `initial-selection.csv` に保存する。候補確定前の除外は `candidate_exclusions`、記事取得後の除外は `results` に記録し、`article-keyword-counts.csv` に除外語と候補適合フラグを追加した。本文未判定の語数は空欄とする。残る取得元・権利・本文品質等の不適合はカテゴリ不適合とまとめず、それぞれの理由を記録する。

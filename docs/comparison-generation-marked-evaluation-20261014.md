# 生成時の適否マークを保持した比較評価（訂正）

作成日：2026-10-14。前回の保存済みデータ・API要求・応答を再利用した。追加生成・追加API採点は行っていない。
指示・出力設計修正後の各3回の実測は[再評価結果](comparison-generation-marked-reevaluation-20261014.md)を参照。以下は修正前の保存結果の整理。


## 今回の評価条件

知りたいのは、生成モデルが返した適否マーク・理由・根拠を保持した処理で、A「一括採点」とB「個別採点＋全体確認」を比べた結果である。新方式の生成記録を持たない旧20本と、不適マークなしで作った人工完全複製T204は、この条件の方式選定の根拠から外す。

T204は完成済みのC01記事をそのまま複製した人工例で、元記事Q438もT204もgeneration_record=nullだった。生成モデルが作った不適マーク付きの記事をBが通した事例ではない。前回この結果をマーク付き処理のBの優劣に結び付けたのは不適切だった。完全複製を一度でも通す実装を不採用とする条件は維持し、今回の条件でそのような見逃しが起きたとは主張しない。

## 保存済み実生成14組の流れ

- 生成側がineligibleを返した6組は採用から除外した。
- 生成側はeligibleだったが、共通の別モデル検証で不適となったC07の2組目をさらに除外した。
- 残る7組をA/Bへ渡した。保存済みの6つの採点要求（各方式3回）を照合し、全42記事入力でgeneration_record、issues、3項目のgeneration_checks、本文、原資料IDが保持されていることを確認した。

不適・未確認のマークを共通処理で除外するのは、A/Bに共通する規則であり、モデル採点の能力差ではない。除外された7組はA/Bの採点APIに渡していない。したがって「マーク付き不適6組を採点モデルへ渡して、モデルが全件見抜いた」とは扱わない。原文と矛盾する生成側のeligibleは採用保証にせず、別モデル検証を続ける。

|段階|組数|扱い|
|---|---:|---|
|実生成結果|14|生成時マーク・理由を保持|
|生成時ineligible|6|共通処理で除外|
|別モデル検証による追加除外|1|共通処理で除外|
|A/B採点対象|7|生成時eligible・確認記録も入力に保持|

C28の2組目は元の生成応答がineligibleだが、判定整合の技術検査で処理状態がneeds_confirmationになった。元の応答と理由は保存され、採用へ復帰していない。

## この条件のA/B結果

|方式|採用数（同順1/同順2/順序変更）|C08|C29|
|---|---|---|---|
|A|7/7/5|採用/採用/不適|採用/採用/不適|

採否が変わったこと自体を、Aの不採用理由にはしない。問題は、不適切な比較を採用したか、記事の内容・根拠に即して判定したかである。少数の正常記事の取りこぼしは許容するという目的に照らす。

3回目だけ順序を変えており、再実行の揺れと順序変更の影響を分離する実験にはなっていない。「提示順が原因で採否が反転した」とは断定できない。

この7組には、完成記事の完全複製は含まれていない。そのため、この結果からマーク付き処理のBが完全複製を確実に除外できると保証することもできない。マークなし人工例の見逃しと、今回の条件の実測結果は区別する。

## 指示・出力設計の問題

実際の指示には「具体的な共通判断がない記事はineligible」「共通検証がeligibleでも本文を再点検」と書かれていた。しかし、以下の点は不十分だった。

1. 適否判定、5軸の品質点、記事間重複を同じ要求で行わせ、適否の各必須項目を採点出力に構造化して要求していなかった。comparison_statusと自由文eligibility_reasonだけでは、採否と各判定根拠の整合を確認できない。eligibility_reasonは空文字も許すスキーマだった。
2. 生成側・共通検証のeligibleという先行結論を入力に渡しており、固定する既知の不適と、改めて判断すべき未確定の適切さの扱いが曖昧だった。先行結論への追随が原因かどうかは未検証である。
3. 共通判断目的について、誰が何を判断する比較か、3者がその判断にどう関係するかを出力項目として要求していなかった。品質点が高いことから適否を決める余地が残った。
4. C08を見た後に「小売・建設・大学をAI業務効率化だけで括らない」という具体例を採点指示へ加えていた。C08はプロンプト調整にも使った例であり、厳密な未使用評価例とは扱えない。

指示・出力契約の修正前に、Aという方式やモデル自体の欠陥と結論付けるのは早計である。次の評価では、既知の不適マークは共通規則で保持し、それ以外の適否について「判断する読者・具体的な問い・3者の役割・各必須条件の判定と根拠」を先に出力させ、適切な記事の品質点とは分ける。直接的な製品選択だけに限定せず、異なる役割でも具体的な工程設計に役立つ比較は認める。分野が異なるだけで却下しない。

現時点ではA/Bの本番方式を確定しない。前回の「順位安定性からBを改善候補にする」という推奨も取り下げ、まず今回の評価条件と指示の整合を修正する。

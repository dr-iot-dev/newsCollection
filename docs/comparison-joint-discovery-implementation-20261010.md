# 共同探索の初期実装と評価

対象：newsWeaveのみ。更新日：2026-10-10（日本時間）。

本稿は初回30回時点の記録。追加30回と継続実装の最新状態は[継続実装・評価](comparison-joint-discovery-evaluation-20261011.md)を参照。

## 結果と現在の状態

追加16発表と既存2発表、計18資料について、ユーザーの明示許可の範囲でOpenAI APIによるshadow評価を実施した。計画はgpt-5.2、個別評価はgpt-4.1、独立検証はgpt-5.1を指定した。初回9回、修正後21回、合計30回で許可された上限に達した。

採用可能な3資料群は0件。修正後に保存した4仮説のうち、2件は3製品の個別評価が完了したが主要項目の根拠不足で不合格、2件は出力エラーまたは上限到達による途中結果である。決定的な充足検査を通過する群がなく、実データの独立検証は一度も呼び出していない。

この結果は「共同探索でも比較記事は作れない」という証明ではない。キーワード検索のみの初期経路、限定された資料群、不正出力、予算不足の影響が残る。設計全体の実装・受入は未完了。WordPress下書き・Publicationの作成、18資料の処理状態の変更、本番設定の変更は行っていない。

## 実装した経路

`comparison discover --mode shadow --seed <UUID>` を追加した。候補未指定なら取得済みカタログ、指定した場合はその資料集合を使う。権利、抽出品質、現在版、根拠と引用範囲、プロンプト注入、既使用資料の除外基準を検査する。V2監査をV1の採用監査へ変換しない。

検証済み事実を日本語二文字索引・英語語句で検索し、同一製品・同一本文を重複排除する。元製品を保持した上位10製品から最大36通りの群を作り、最大3群、各群最大2仮説を詳細評価する。比較目的・読者・主要項目3〜5件・任意項目0〜2件を3資料から共同生成する。料金や危険度は固定の必須項目にしない。

各セルの事実IDは自身の資料の検証済み事実へ結び付ける。数値、出典、条件、プラン、版等を検査する。unknownを非対応へ変換しない。主要項目は全3製品、表示する全項目は製品側と主発表側の両方で過半数を要求する。得点で不合格を上書きしない。

決定的な検査を通った群だけ、実際の計画・評価モデルと異なるモデルで6項目の独立検証を行う。同じ選択課題、行の質問、充足、根拠と条件、編集側の採用理由、重要情報の欠落をすべてpassとし、阻害事項がない場合だけeligibleとする。

実行入力、方針、モデル、プロンプト、スキーマのhashに基づき、正常に保存された完了工程を再利用する。不正出力は1回だけ修復し、同じ失敗入力を無制限に再試行しない。途中評価も保存する。一つの仮説の出力不正によって、同じ群の別仮説まで打ち切らない。

## 実データ評価後の修正

以下はローカル試験済みだが、今回の30回に含まれるAI評価ではまだ測定していない。

- 仮説の各項目について、全製品の回答案と事実IDを `question_support` に対応付ける。主要項目の未記載、他製品の根拠、条件消失、表示項目の過半数不足を計画時点で検査し、個別評価へ進む前に拒否する。意味上の適合・重要情報の欠落は引き続き独立検証が必要である。
- 群の順位へ非元製品の重複を考慮するMMRを導入した。相互キーワード関連度の正規化値を0.7、既選択群との重複を0.3とする暫定的な設計値で、36群の点数と選択を監査へ保存する。類似度を比較適性の承認には使わない。根拠付き役割プロフィールによる絞込は残作業である。
- 重なる引用周辺を一つの範囲に統合し、事実IDと原文位置を保持して送る。元の範囲の和集合から新たな文字位置を追加せず、原文を削らない。上位10資料の周辺本文は199,939文字から27,257文字へ減った（86.4%）。これは周辺本文だけの重複削減率であり、API入力全体やトークン数が同率で減ると主張しない。
- `--budget-id` で目的や入力の改訂を同じ呼び出し予算へ束ねる。予約を呼び出し前に保存し、PostgreSQLのadvisory lock、checkpoint実行時のSQLiteの書込ロックで並行予約の上限超過を防ぐ。予算台帳のhashも検査する。ID未指定の場合は同一入力の再開だけが同じ予算となる。
- 確定群のhash、現在の資料・権利・抽出・証拠・製品対応、実際のAI実行と出力、引用の再結合、独立モデルを追加APIなしで再照合する。記事送信への接続は未実装である。

新しいMMRのローカル順位は、元製品と「cloudpack＋ZEIJAX」「セキュリティ診断+(プラス)＋Cloudbric」「GMO ASM＋SECURE-AID Apps」の3群となった。用途・役割が合うという結論ではなく、後段で確認する候補である。例えばASMが同じ選択課題の代替にならない場合には不合格にしなければならない。

## 再現と次の評価

```sh
news-weave comparison discover --mode shadow \
  --seed <元資料UUID> --candidate <候補UUID> --candidate <別の候補UUID> \
  --budget-id <同じ評価巡回で保持するUUID> \
  --maximum-groups 3 --maximum-api-calls 30 \
  --exclusion-baseline <既使用資料JSON> --output <監査JSON>
```

モデルは既存の `AI_COMPARISON_PLANNER_MODEL`、`AI_COMPARISON_ASSESSOR_MODEL`、`AI_COMPARISON_VERIFIER_MODEL` を使う。独立モデルが計画・評価モデルと同じ場合はAPI呼び出し前に停止する。eligibleは終了コード0、保留は2、入力・DBエラーは1。

許可された30回は消費済み。修正後の実データ再評価には追加の呼び出し許可が必要である。次の評価では、計画時の根拠対応、入力の重複削減、群の多様性を測定し、独立検証へ到達できるかを確認する。方式の有望性を評価するためにも、既存の品質条件を緩めず、出力不正と真の資料不足を分けて記録する。
